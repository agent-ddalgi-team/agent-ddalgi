| A variant `0d40cd02-…` | A | `not_found` | `conflict` | A의 `result.json` |
| C 기준 `bc4d7336-…` | C | 추가 확인 필요 (C 주석: conflict) | 추가 확인 필요 (C 주석: conflict) | C 일일 작업일지 |
| C variant `bb47e300-…` | C | 추가 확인 필요 (C 주석: conflict) | 자료에서 확인되지 않음 (not_found) | C 일일 작업일지 |

- C 기록의 값은 **문서 본문의 안내 문구**를 옮긴 것이다. 본문의 "추가 확인 필요"는
  `conflict`와 `needs_confirmation` **양쪽에 쓰이므로 문서만으로는 둘을 구분할 수 없다.**
  괄호 안 상태는 C의 주석이며 A가 JSON으로 재확인한 값이 아니다.
- **형식 검사 통과와 항목 의미 정확성은 다른 문제다.** 네 작업 모두 상태별 facts 개수 규칙은
  지켰고 `INVALID_OUTPUT`도 나지 않았다. 문제는 같은 종류의 입력에서 어느 항목에 배정되는지가
  작업마다 달라 보인다는 점이다.
- A와 C의 **입력·코드·프롬프트·모델·설정이 동일했는지 확인되지 않았다.**
  따라서 원인을 "동일 조건의 반복 실행 불안정성"으로 단정하지 않는다.
- **추출 의미 정확성 관련 미해결 이슈로 남긴다.**

**이슈 2 — 본문의 라벨 접두어 잔존**

C 기록은 본문에 "회사 개요:", "사업 분야:" 같은 라벨 접두어가 남는다고 적었다.
**출력 형식 검토 항목으로 기록한다.** A가 앞서 관찰한 문장 표현 차이와 같은 원인이라고 단정하지 않는다.

두 이슈 모두 이번에 수정하지 않았다. 상세 증거는 비공개 경로에만 있다.

### 환경 차이 — 재시험 요청이 아니라 기록

B가 쓴 백엔드는 **로컬 사본**(`FINAL_geosan`)이고 모드는 `mock`이었다.

이 차이는 기록만 하고, 같은 시험을 다시 하라고 요청하지 않는다.

### R08 판정 근거 정리

R08은 "서로 다른 가짜 입력 2종에서 각 작업의 **API·화면·파일**이 연결되어 대조"를 요구한다.
**최종 판정과 근거 취합 상태는 다른 것이다.**

**최종 판정: 완료.** 완료 범위는 **"C 검증 환경의 가짜 입력 2종 통합 시험"** 이다.

| 근거 구분 | 내용 | 상태 |
|---|---|---|
| **직접 근거 — C의 두 작업** | `bc4d7336-…`(기준)·`bb47e300-…`(variant) 각각에서 API 결과·MD·DOCX 3자 대조 일치, 입력별로 다른 결과 생성 | **완료** |
| 위 두 job의 화면 내용 대조 | C 기록에 job 단위 연결이 없음 | **미확인** |
| **보조 근거 — A의 두 작업** | `1009d15b-…`·`0d40cd02-…`의 API·MD 대조 (자동 26건 + MD 8건) | 보존 |
| B의 브라우저 직접 확인 | B 기록의 미수행·월요일 이월 상태 그대로 유지 | 미수행 · 이월 |

- 완료는 **C 검증 환경 기준**이며, 가짜 테스트 자료 기준이다.
- A의 시험은 직접 근거가 아니라 **별도 보조 근거**로 남긴다. 두 환경의 job을 합치지 않았다.
- 브라우저 다운로드 성공을 화면 내용 대조로 확대하지 않았다.
- **항목 배정 이슈(9-3 이슈 1)가 미해결이다.** R08 완료가 전체 품질이나
  실제 기업 자료 검증의 완료를 뜻하지 않는다.
